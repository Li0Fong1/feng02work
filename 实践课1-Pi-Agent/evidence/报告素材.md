### 3.3 选择依据与认识

- **任务复杂度如何影响选择**：一句话概念解释、格式转换、文件摘要这类低复杂度任务，用 `deepseek-flash` + 低思考级别即可，响应快、用量省；涉及多步推理、代码重构方案、跨文件排查时，改用能力更强的模型并提高思考级别更稳妥。
- **图片任务优先看能力而非等级**：`deepseek-v4-pro` 不支持图片输入，因此任务四 B 必须回到 `deepseek-flash`。
- **思考级别不是换模型**，也不是"显示 / 隐藏思考文本"，而是模型的推理强度设置；部分模型不支持调整，应换用支持该设置的模型完成练习。
- **较高思考级别不保证每次答案更好**，代价是等待时间和用量增加；本次两个级别对同一短问题的回答质量接近，正说明不宜盲目拉满。
- 若快捷键无效，用 `/model`、`/thinking` 命令，或 `/hotkeys` 核对当前绑定。

## 四、任务四：引用代码文件与粘贴小图片

### 4.1 A 使用 `@` 引用代码文件

在 `pi-test` 文件夹创建 `hello.py`：

```python
def add(a, b):
    return a + b

print(add(2, 3))
```

先在本地核对运行结果：

```text
$ python3 hello.py
5
```

在该文件夹启动 Pi，输入 `@`，**从候选列表中选中 `hello.py`**（也可继续输入文件名筛选），再发送提示词「请解释 @hello.py 的功能，说明运行后输出什么。只解释，不修改文件。」模型真实回复：

```text
`hello.py` 是一个最小示例脚本，没有修改任何文件。

组成
1. def add(a, b): return a + b：定义函数 add，接收两个参数并返回它们的和。
   这里的 + 由传入对象的类型决定：数字是算术相加，字符串是拼接。
2. print(add(2, 3))：调用 add(2, 3)，在模块被直接执行时打印结果。

运行输出
5
具体来说，add(2, 3) 返回整数 5，print 将其转为字符串 "5" 并输出，末尾带一个换行符。

补充
- 脚本没有 if __name__ == "__main__": 保护，因此被 import hello 时也会立即执行 print。
- 传入 add("a", "b") 会得到 "ab"，传入不兼容类型会抛 TypeError。
```

真实界面中输入 `@` 后弹出候选列表（`hello.py` / `test-image.png` / `make_test_image.py`），按 Enter 选中 `hello.py` 后输入框出现 `@hello.py ` 引用标记（见 S4a、S4c）。检查点全部满足：回复解释了 `add` 函数、给出输出 `5`，且明确未修改文件。**只打出 `@` 而未从候选列表选中文件，不算完成引用**。

### 4.2 B 粘贴小图片并测试

素材：约 200×200 像素的 `pi-test/test-image.png`，白色背景，左侧一个蓝色实心方块，右侧黑色数字 `7`。由 `make_test_image.py` 用 Python 标准库生成（不依赖 Pillow），可复现。

> 【原始小图片插入位】在此插入 `pi-test/test-image.png`，便于核对识别结果。

TUI 操作：先把**图像内容**截取到剪贴板（不是复制图片文件路径），切换到明确支持图片输入的模型（`deepseek-flash`，`images=yes`），按 `Alt+V` 粘贴（当前版本也可能支持 `Ctrl+V`，macOS 通常以 `/hotkeys` 为准），确认出现图片附件或图片输入提示后发送「请描述图片中的颜色、形状和数字。」本机把 PNG 的真实像素写入系统剪贴板 CF_DIB 后按 `Alt+V`，Pi 生成 `pi-clipboard-….png` 附件并调用 `read` 工具读取（见 S5a）；命令行中另用 `@test-image.png` 复现同一识别结果。模型真实回复：

```text
颜色
- 背景：白色
- 左侧：一种中等亮度的蓝色（偏"宝蓝/亮蓝"，饱和度较高的蓝色）
- 右侧：黑色

形状
- 左侧是一个正方形的蓝色实心色块，四条边都是直的、四个角都是直角，颜色完全均匀
- 右侧是一个由若干小黑方块（像素块）拼接而成的图形：顶部一条长的水平黑条，
  右端向下延伸，接着沿斜线以阶梯方式向左下方递进，整体呈"右上横、右下斜"的折线形

数字
- 这个黑色像素图形识别为数字"7"，只是被画成了粗块状、阶梯状的像素样式

整体构成像是"蓝色方块 + 黑色数字 7"的极简图标式排版。
```

## 五、任务五：安装并使用一个插件

### 5.1 概念辨析

- **插件（Extension）**：增加工具、命令、界面或事件处理的扩展点。
- **Skill**：提供特定任务的操作说明及支持文件（`SKILL.md` + 脚本 + 参考材料）。
- **Pi Package**：可以包含插件、Skill，也可以包含主题和提示模板。

**安装一个包不代表其中所有资源都已加载**，因此本任务把"安装成功""加载成功""功能可用"分开验证。

### 5.2 选型记录

| 项目 | 内容 |
|---|---|
| 名称 | `pi-web-access` |
| 来源 | Pi Packages `https://pi.dev/packages`，npm 包 `pi-web-access@0.47.0` |
| 安装命令 | `pi install npm:pi-web-access`（个人级安装） |
| 项目级安装 | 先进入项目目录，用 `pi install npm:pi-web-access -l`，必要时加 `--approve` |
| 作用 | 为 Pi 增加 `web_search`、`source_check`、`fetch_content`、`get_search_content` 等联网工具 |
| 所需配置 | 零配置可用（Exa MCP）；可选在 `~/.pi/agent/web-search.json` 配置更多搜索提供商 |

### 5.3 安装与加载证据

```text
$ pi list
User packages:
  npm:pi-web-access
    C:\Users\Lenovo\.pi\agent\npm\node_modules\pi-web-access
```

`pi list` 只能证明"已安装"。为证明"已加载"，对比正常启动与 `--no-extensions` 启动时的可用工具列表：

```text

[--no-extensions 启动]
read, bash, edit, write
```

差值正好是插件注册的四个联网工具，说明包在重启后的会话中被真实加载，而不只是写进了设置文件。TUI 中对应的验收画面是重启 `pi` 后的 `[Extensions]` 区域与插件名称；本机启动界面确实显示 `[Extensions]` 下的 `pi-web-access:dist`（见 S1 与 S6a 截图）。

## 六、任务六：让 AI 安装 PPT Skill（选做，已完成）

### 6.1 给 AI 的指令与执行方式

## 八、遇到的问题与解决

| 现象 | 原因 | 处理 |
|---|---|---|
| `pi -p` 第一次挂起数分钟无输出 | 非交互模式下 stdin 未关闭，进程等待输入 | 加 `< /dev/null` 并配合 `timeout`，会话正常返回；采集脚本已固化该写法 |
| `git clone https://github.com/...` 失败 | 本机代理下 `github.com:443` 的 git 通道不通 | 改用 `api.github.com` 取目录树 + `raw.githubusercontent.com` 逐文件下载，并固定同一 commit |
| PowerShell `Add-Type` 生成图片被安全策略拦截 | 运行时编译 .NET 代码被禁止 | 改用纯 Python 标准库（`zlib` + `struct`）直接写 PNG，顺带产出可复现脚本 |
| `validate.py` 报缺 `defusedxml` | Skill 假设依赖预装，本机没有 | 按实际补齐 `defusedxml` / `lxml` 后重跑，校验全部通过 |
| `fetch_content` 的 `readable` 模式提示内容不完整 | example.com 可见文本过短且含脚本 | 按工具提示改用 `raw` 模式读取原始 HTML，取到 `<title>` |
| 证据脚本首次重跑时 S8 提取失败 | 正则替换串末尾反斜杠导致 `re.PatternError` | 改为字符串 `replace` 处理转义，重跑一次通过 |

## 九、小结与心得

1. **分层验证比"看起来成功"更重要**：安装包 ≠ 加载资源 ≠ 功能可用 ≠ 产出正确。任务五用工具列表差值证明加载，任务六把安装、发现、调用、生成拆成四层，都是这个思路。
2. **能力差异要先查再用**：`pi --list-models` 一眼看出只有 `deepseek-flash` 支持图片，避免了在不支持的模型上反复试错。
3. **文档里的环境假设不是本机事实**：Skill 声称 pptxgenjs 预装、指导书提示 npm 未必可用，都以实测为准，先检查再补齐依赖。
4. **凭据安全是硬约束**：全程未在报告、证据或仓库中出现 `auth.json` 内容、完整密钥或授权回调链接；`.gitignore` 已提前排除。
5. **界面截图来自真实屏幕**：模型选择器、`@` 候选列表、图片附件、`[Extensions]`、`[Skills]` 这些交互证据均来自真实 Windows 终端窗口的屏幕捕获（ImageGrab 抓取物理像素），共 16 张，未做任何渲染或合成；命令行文本证据另存于 `evidence/`，二者互为印证。
